## 1. 主题定义

本主题归并“候选因子为什么在回测里看起来有效、但在样本外或实盘中失败”这一类知识。它不是一个单独的因子主题，而是阶段 2 后续所有特征设计都要共用的风险控制主题。覆盖文献包括加密货币机器学习实盘失败、因子层次聚类、噪声 Alpha 下信号筛选、商品展期统计和跨资产时序因子增强。它们的市场和频率不同，但共同指出：如果没有样本外切分、交易可实现性、冗余暴露控制和失败条件记录，特征挖掘很容易把噪声、执行偏差或制度差异误判为可交易 Alpha。

`doc_04` 是本主题的负面案例核心。其三套机器学习交易系统在 Binance ETHUSDC 永续合约上实盘部署，经历了从 bar 特征到 tick 流特征、从 142 个特征到 45 个 streaming 特征、从 10 倍到 50 倍杠杆的升级，但最终实盘结果仍与随机无显著差异。`doc_10` 讨论多重检验和虚假发现，提醒严格 p 值筛选并非总是最优。`doc_05` 提供因子冗余与聚类降维工具。`doc_14` 和 `doc_15` 则从商品展期和跨资产配置角度提醒样本选择、回测口径和可复制性问题。

## 2. 核心机制与共识

第一个共识是，预测准确率不等于交易收益。`doc_04` 明确指出 execution-prediction mismatch：模型预测目标与真实成交、止盈止损、滑点、延迟和持仓约束之间存在断裂。V1 系统在 walk-forward 中达到 AUC=0.85，但实盘日均 PnL 约为 0.12 美元；V3 使用更短窗口和 streaming 特征后，仍产生负的累计基点收益。这个结果对本项目尤其重要，因为期货日内因子容易在“未来几秒价格方向”上看似有效，但一旦考虑盘口排队、手续费、最小变动价位和强制平仓，信号可能无法交易。

第二个共识是，复杂化不自动带来稳健性。`doc_04` 把过拟合描述为 complexity escalation：失败后继续增加特征、模型和杠杆，可能只是在训练集上更贴合噪声。`doc_15` 在月度配置中承认时序因子有强体制依赖，不存在任意市场环境都稳定盈利的主动择时因子。迁移到本项目后，应把“失败与方向翻转”写进特征设计，而不是只记录成功窗口。

第三个共识是，冗余暴露需要显式管理。`doc_05` 使用相关系数距离 `d_{i,j} = sqrt((1-rho_{i,j})/2)` 对因子进行层次聚类，说明高度相似的因子不应被视为独立信息。`doc_10` 则从噪声 Alpha 角度说明，在大量候选信号中，零信号和弱信号会大量存在，严格筛选和过度筛选都可能出问题。对期货日内特征库来说，多个窗口、多个盘口档位和多个标准化版本常常只是同一信息源的变体；进入登记册前应做相关性、消融和增量解释检验。

第四个共识是，交易可实现性不是回测之后的附录，而是特征定义的一部分。`doc_14` 的商品展期研究强调成交量和持仓量迁移决定实际移仓窗口；`doc_15` 批评理论财富线忽略交易摩擦、买卖价差、跟踪误差和流动性约束。这些证据共同要求：如果一个日内特征需要在盘口薄、换月临近或冲击成本高的时段频繁换手，它的适用条件必须写在特征卡中。

## 3. 关键公式与诊断工具

### 3.1 随机游走 TP/SL 基准

来源：`doc_04`

```text
P(TP first) = SL / (TP + SL)
```

该公式用于提醒非对称止盈止损会制造表面胜率优势。若止盈很近、止损很远，即使价格随机游走也可能出现较高胜率，但期望收益未必为正。日内特征检验中，如果使用方向准确率或胜率，必须同时报告平均盈亏比、回撤、交易成本和持仓分布。

### 3.2 因子相关距离

来源：`doc_05`

```text
d_{i,j} = sqrt((1 - rho_{i,j}) / 2)
```

该距离可以用于候选特征去重。对本项目来说，可在开发集内计算候选特征收益序列、信号序列或 IC 序列的相关性，再按距离聚类。若两个特征同属一簇，登记册应保留它们的关系：一个作为主版本，另一个作为窗口或口径变体。不能把高度相关的多个版本当成独立证据累加。

### 3.3 信息比率与虚假发现

来源：`doc_10`

```text
IR = alpha_hat / omega_hat
```

以及 FDP 估计：

```text
pi0_hat(lambda) = #{p_i > lambda} / ((1 - lambda) * m)
```

这些方法原本用于月度基本面信号，但在本项目中可迁移为“候选池管理”的思路：记录每批候选的数量、通过率、失败率、样本内外落差和重复发现程度。不要只看单个最优特征，而要看整个批次的 false discovery 风险。

### 3.4 波动率截断与信号幅度限制

来源：`doc_15`

`doc_15` 使用 clipped volatility 和 `tanh` 限制信号到权重的映射幅度。迁移到日内场景时，可把它理解为两个风险控制原则：极低波动时期不要无限放大仓位，极高波动时期不要让信号幅度不受控；多信号融合时先限制单个信号贡献，再做组合。此处只是方法启发，不代表月度宏观配置公式可直接复用于秒级期货。

## 4. 检验与复核共识

本主题建议把后续特征检验分成三道门。第一道门是“真实性门”：特征公式、字段和 locator 必须可回溯；原文没有说的内容必须标为扩展或缺失；`doc_01`, `doc_08`, `doc_09`, `doc_11` 这类硬失败样本不能进入主题强证据。第二道门是“预测门”：明确预测目标、horizon、标签基准和样本内外切分，避免把同期关系当成未来预测。第三道门是“交易门”：引入手续费、延迟、最小变动价位、成交量约束、最终日内平仓和极端行情处理。

对于模型和参数选择，`doc_04` 支持 walk-forward 或后验延伸检验，而不是只做一次随机切分。参数必须在开发或验证集选择，并在测试集冻结。若某个参数只在特定窗口、特定品种或特定市场状态有效，应在特征登记册里记录“适用状态”，不能把局部结果推广成通用结论。

人工复核上，warning 不应被视为失败，但也不能静默放过。图表、图注、章节级 locator 可以进入主题文档，但要标注“待复核”。如果 warning 高频出现，说明 validator 需要升级证据簇匹配；如果 original 漏抽导致 extension 悬空，应该通过 repair 补 original 或降级为 inspiration，而不是把错误改成 warning。

## 5. 文献分歧与失败模式

第一类失败是样本内优秀但实盘失效。`doc_04` 是最典型案例，它说明高 AUC、更多特征和更细粒度数据并不能自动转化为实盘收益。

第二类失败是统计显著但经济不可交易。`doc_10` 提醒多重检验中的显著性可能包含大量虚假发现；`doc_15` 指出理论财富线可能因忽略摩擦而不可复制；`doc_14` 强调流动性与容量限制。对本项目来说，如果一个特征只能在无成本、无延迟、无限深度假设下赚钱，应直接判为不可入池。

第三类失败是冗余暴露。`doc_05` 显示聚类能减少重复因子风险，但过度聚类又会损失信息。日内特征中，`3/5/15/60` 秒窗口可能同时抓住同一冲击，只是滞后不同；如果不做聚类和消融，会高估独立样本和独立信号数量。

第四类失败是迁移边界被忽视。`doc_14` 是商品期货研究，和本项目市场更近；`doc_15` 是跨资产月度配置，频率差异很大；`doc_10` 是基本面月度信号；`doc_04` 是加密永续合约。它们可提供机制和检验框架，但不能在不重验的情况下成为期货日内单合约特征的实证证据。

## 6. 项目适配与操作规则

后续路线一和路线二输出特征时，应强制附带以下字段：特征名称、所需字段、计算公式、窗口和下标、设计理由、适用条件、异常处理、预测标签、检验设计、预期方向和放弃条件。路线二还要额外附 `lit_id + page/chunk/source_locator`。如果只是一条方法启发，应进入 idea backlog 或 extension，不得直接进入候选因子库。

首轮建议建立批次级质量指标，而不是只看单篇是否通过：`first_pass_rate` 用于观察 prompt 和 schema 的抽取质量；`final_pass_rate_after_repair` 才作为进入下一批的门槛。`doc_01`, `doc_08`, `doc_09`, `doc_11` 当前应记录为 `machine_fail_human_needed`，不是删除，也不是混入主题结论。它们的失败原因可以反推下一步 repair pass：区分 `missing_original_evidence`、`locator_granularity_mismatch`、`fabricated_locator` 和 `schema_violation`。

本主题给出的直接交付价值是一个“防过拟合和防幻觉”检查清单：所有候选特征必须通过真实性门、预测门、交易门和冗余门。未通过真实性门的内容不参与主题强结论；未通过预测门的内容只能作为同期解释；未通过交易门的内容只能作为研究现象；未通过冗余门的内容只能作为已有特征的变体记录。
